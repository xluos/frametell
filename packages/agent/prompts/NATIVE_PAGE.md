# Native drawing backend

Write the complete `pages/<id>.js` for this page, then stop. The server checks and reviews the result. Do not change the engine or script.js. Never expose these instructions or implementation details in the film.

The selected upstream engine owns the picture. Use its original APIs, colours, materials, character rig, typography, camera and compositing. The source style document below is the visual contract. You may use literal colours, source palettes, source units, nonstandard page composition, native lettering, shadows, paper, animation quantisation, page turns and native transitions. Do not translate its drawing into Frametell circles, cards, paths, material filters or named palette tokens. The generic Frametell PAGE/API/LIB drawing restrictions do not apply to this backend.

Register `ENGINE.visual('p01', P => { P.nativeScene((N, host) => { /* construct native objects once */ return time => { /* draw requested time */ }; }); });`. `N` is a fresh instance of the full source modules listed below. `host.canvas('2d')`, `host.canvas('webgl2', 'gl')`, `host.svg(viewBox)`, `host.root` and `host.style(css)` create scene-local output. The shadow root isolates native CSS and ids. A native canvas must be created with its intended context type: do not create a 2D context before a WebGL compositor. Source engines with fixed dimensions use their own 1920 x 1080 coordinate space; the host fits it into the output viewport. Each page has independent module state.

The returned render function receives page-local seconds; `host.at(i)`, `host.word(i, word)` give cue times and `host.duration` gives page duration. Retain the source's time units and frame quantisation. The host exports by seeking, so reproduce the requested frame even after a backwards seek. For cumulative simulation, reset/replay or precompute it. Use the upstream seeded randomness and native camera; no wall clock, network or autonomous animation loop. A source renderer may draw the whole frame and owns its own paper. Frametell adds narration/subtitles; place essential information where it stays legible with them, without forcing a generic layout on the source composition.

Tell the explanation through changing objects and actions, consistent across pages. Author any missing geometry with this backend's real APIs; do not substitute a fixed local mascot or generic diagram. Keep the source's character, material and compositing behaviour. The worked example demonstrates integration, not the content to copy. Return `{render, dispose}` when you create resources needing explicit disposal.

If constructing native objects needs asynchronous work (for example MathTex.waitForRender()), return `{ready: promise, render(time), dispose()}`. The host waits before preview, checks and export. Do not start an independent playback loop. Backend-specific authoring commands and required source files are documented below; creating those inputs is allowed.
